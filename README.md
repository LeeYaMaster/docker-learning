# Docker 动手学习营

欢迎。这是一套循序渐进的 Docker 动手实验，专门写给已经会写程序、想把容器真正跑起来的人。

你不会在这里看到一堆空泛概念。每个实验都有可复制的命令、明确的预期结果，以及若干需要你自己动手的小练习。一路做完，你会得到一个完整的「留言板」小应用：Web + MySQL + Redis，全部用 Compose 编排。

应用逻辑刻意保持很小，好把注意力留在 Docker 上。

## 环境要求

- 本机已安装并运行 Docker Desktop，终端里可以执行 `docker` 和 `docker compose`。
- 需要一个浏览器（实验 01 会用 nginx 在 8080 端口出页面）。
- 本学习营假定你本机可能已经安装了 MySQL、Redis。因此 Compose 里**不会占用默认端口**：
  - Web：`8080`
  - MySQL：宿主机 `3307` → 容器 `3306`
  - Redis：宿主机 `6380` → 容器 `6379`

请先确认这几个宿主机端口空闲。若 8080 被占用，可在对应命令或 Compose 里改成别的端口，但文档里的示例一律按上面这组来写。

## 如何开始

在终端进入本项目根目录（也就是本 `README.md` 所在的目录），然后打开第一个实验：

```bash
cd labs/01-hello-container
```

每个实验目录里都有：

- `README.md`：目标、逐步命令、预期结果、小练习、常见坑
- `answers.md`：小练习的参考答案。**先自己做，再打开它**，效果更好

命令里会写清「请在哪个目录执行」。复制时注意当前路径，不要在错误的目录里构建镜像。

同一时间请只占用一次 `8080`。例如先停掉实验 01 的 nginx，再运行实验 02 的 Python 服务。实验结束时，README 里都有收尾命令。

## 端口说明

| 用途 | 宿主机端口 | 容器端口 | 出现在 |
|------|------------|----------|--------|
| Web（nginx / Python / 留言板） | 8080 | 80 或 8000 或 5000，见各实验 | 01、02、04、06、07、08 |
| MySQL | 3307 | 3306 | 仅 06（以及 08 若接上留言板） |
| Redis | 6380 | 6379 | 仅 06（以及 08 若接上留言板） |

为什么不映射 `3306`、`6379`？因为你本机很可能已经跑着 MySQL 和 Redis。容器里的服务仍然使用它们自己的默认端口，只是在发布到宿主机时换一个口，避免冲突。留言板容器之间互连走的是 Compose 网络内部端口，不受这组映射影响。

## 常见问题

**`docker` 或 `docker compose` 命令找不到 / 连不上引擎。**  
先确认 Docker Desktop 已经启动，托盘图标不再是「正在启动」。然后新开一个终端再试 `docker version`。

**`Bind for 0.0.0.0:8080 failed: port is already allocated`。**  
8080 被占用了。用 `docker ps` 看看是不是上一个实验的容器还在：

```bash
docker ps
docker stop <容器名或 ID>
```

若是本机别的程序占用，可把命令里的 `8080` 改成 `8081`，浏览器也改访对应端口。

**留言板起不来，日志里报数据库连接失败。**  
先看 `docker compose ps`，确认 `db` 的状态是 `healthy` 后再观察 `web`。MySQL 第一次初始化往往需要十几秒到半分钟。详见 [实验 06 的常见坑](labs/06-compose-guestbook/README.md)。

**`docker compose down` 之后留言还在，想清空怎么办？**  
数据在具名卷里。`down` 默认不删卷。清空请用实验 06 README 里的说明（`down -v`），这会删掉练习数据。

**Apple Silicon（M 系列）Mac 能不能做？**  
可以。本实验使用的官方镜像都提供 arm64 变体，一般不必加 `--platform`。若某条命令拉镜像特别慢，多半是网络问题，换网络或重试即可。

**要不要先学完所有概念再动手？**  
不用。直接从实验 01 开始敲命令，概念会在你看到输出时变得具体。
